# Papin Ads

Веб-прототип управления TON-кабинетом Telegram Ads. Один администратор, отдельный хост, интерфейс на русском языке. Telegram-бот управления запланирован на следующий этап.

## Возможности

- Синхронизация аккаунта и всех объявлений каждые 5 минут, дневная история за 14 дней, CSV.
- Шаблоны из существующих объявлений и редактор. Изменение шаблона не редактирует опубликованную рекламу.
- Массовый запуск рекламы в ботах: список usernames, шаблон, бюджет на объявление, начальная CPM. Перед созданием показываются разрешённые площадки и суммарный бюджет.
- Сохраняемая в SQLite очередь с ключом идемпотентности на каждое объявление, восстановлением после перезапуска и сверкой неопределённого результата. Отмена останавливает оставшиеся задания; созданная реклама сохраняется.
- Ручная CPM, пауза и возобновление. При ручном действии стратегия для объявления выключается.
- Автоподбор CPM под темп показов: цель, период, границы CPM и порог остановки по расходу на каждое объявление. Шаг по умолчанию 10%, допуск 20%, задержка применения 60 минут, окно наблюдения 60 минут, между изменениями 120 минут. Отсчёт новой стратегии начинается после активации объявления.
- Общая пауза стратегий и журнал причин каждого изменения.

Алгоритм постепенно корректирует CPM по наблюдаемому темпу; это не дихотомия и не обещание минимальной рыночной ставки. Малая аудитория, конкуренция, модерация и задержки Telegram могут помешать достижению цели. Порог остановки по расходу/показам проверяется после синхронизации и не является мгновенным ограничением платформы. Жёстко выделяемый бюджет — `initial_budget` объявления; сервис не пополняет его автоматически.

Существующие объявления импортируются с выключенным автоподбором. Первая синхронизация создаёт шаблоны только из текстовых размещений в ботах. Создание пачки выделяет средства из свободного баланса в отдельные объявления; повторное подтверждение одного предпросмотра не создаёт новую пачку.

Режим отдельных `start`-меток хранит соответствие в пачке и ссылке объявления. Он **не регистрирует метки в Minishop** и не собирает оплаты/выручку. При использовании ссылки шаблона сохраняется прежняя атрибуция. Массовое создание в этом прототипе поддерживает размещение в ботах; существующие поисковые объявления доступны для просмотра и ручного управления.

## Развёртывание

Требуются Docker Engine с Compose v2, DNS домена на сервер, открытые 80/443. Репозиторий не содержит токенов или базы.

```sh
cp .env.example .env
# Заполните TelegramAds_API_Token, SESSION_SECRET (минимум 32 символа),
# ADMIN_USERNAME, ADMIN_PASSWORD_HASH, DOMAIN и PUBLIC_URL.
mkdir -p data
sudo chown 10001:10001 data
chmod 700 data
chmod 600 .env
docker compose up -d --build
docker compose ps
```

Хеш пароля можно получить без передачи пароля в аргументах команды:

```sh
python -c 'from getpass import getpass; from app.config import hash_password; print(hash_password(getpass()))'
```

Значение `ADMIN_PASSWORD_HASH` в `.env` заключайте в **одинарные кавычки**, чтобы Compose сохранил символы `$` буквально. `SESSION_SECRET` генерируется через `python -c 'import secrets; print(secrets.token_urlsafe(48))'`. После смены `SESSION_SECRET` старые сессии недействительны. `PUBLIC_URL` должен точно совпадать с внешним origin (протокол и домен, без завершающего `/`).

Приложение работает от UID 10001, порт 8000 доступен только внутри Docker. Caddy получает и продлевает HTTPS-сертификат. Вход защищён PBKDF2, подписанным HttpOnly/Secure/SameSite cookie, проверкой Origin/CSRF и ограничением попыток. API-токен доступен только серверу и передаётся только `promoteapi.telegram.org` без перенаправлений. Используйте отдельный аккаунт администратора; многопользовательские роли и 2FA пока не реализованы.

Открывайте интерфейс по `PUBLIC_URL`, а не как локальный HTML-файл. Сервер включает CSS и JavaScript в основной документ, чтобы оформление и обработчики входа не зависели от отдельных запросов к ресурсам. Встроенный JavaScript разрешён CSP только по SHA-256 его содержимого; `unsafe-inline` для скриптов не используется. Главная страница отдаётся с `Cache-Control: no-store`.

Рабочая папка сервера: `/opt/papin-ads`; закрытый bare-репозиторий: `/srv/git/papin-ads.git`. Клонирование доступно владельцу SSH-ключа:

```sh
git clone root@ads.papin-free.site:/srv/git/papin-ads.git
```

Обновление после push:

```sh
ssh root@ads.papin-free.site
cd /opt/papin-ads
git pull --ff-only
docker compose up -d --build
```

## Проверка и локальная разработка

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
node --check app/static/app.js
```

Тесты используют поддельный API: реальная реклама и баланс не изменяются. Проверяются авторизация, CSRF, валидация расходов, подтверждение пачки, повторы после неопределённой доставки, отмена, отсрочка модерации, ручное вмешательство и решения алгоритма. Для локального старта задайте переменные окружения, `DATA_DIR=./data`, `COOKIE_SECURE=false`, `PUBLIC_URL=http://localhost:8000`, `RUN_WORKER=false`, затем `.venv/bin/uvicorn app.main:create_app --factory`. Python сам не читает `.env`; её загружает Compose.

`/healthz` проверяет доступность приложения и базы. Состояние Telegram Ads видно на странице после входа: последний успешный sync и ошибка API. Проверка `/healthz` сама по себе не означает успешную связь с Telegram.

## Резервная копия

База содержит статистику, очередь и историю. Скопируйте её SQLite backup API, а не отдельным копированием файла при активном WAL:

```sh
docker compose exec -T app python -c "import sqlite3; src=sqlite3.connect('/data/papin-ads.sqlite3'); dst=sqlite3.connect('/data/backup.sqlite3'); src.backup(dst); dst.close(); src.close()"
```

Сохраните `data/backup.sqlite3`, приватную `.env` и Caddy volumes в отдельном закрытом хранилище. Восстановление: остановить app, вернуть базу и её владельца UID 10001, запустить app. При неопределённом создании сервис сначала ищет объявление по уникальному заголовку/ссылке; спустя 23 часа без найденного результата потребует ручной проверки вместо автоматического повторного расхода.
