# Реализация подбора и универсальных пачек

## Модули и поток данных

`static/app.js` → аутентифицированные FastAPI endpoints → `Discovery`/`Engine` → Telegram MTProto или рекламный HTTPS API. Все вызовы внешних API выполняет сервер; секреты не передаются браузеру.

- `app/targets.py`: типы целей, парсеры usernames/фраз, ключи сопоставления, извлечение целей из импортированных объявлений, проверка совместимости шаблона и ссылки, разрешение целей рекламным API, построение target payload.
- `app/discovery.py`: `TelegramDirectory` (Telethon), рекомендации/поиск, SQLite-кэш, импорт CSV, присоединение исследовательских записей и первой стороны, вычисление групповых CTR/CPC.
- `app/telegram_login.py`: единственная интерактивная точка создания пользовательской Telegram-сессии. Нет публичного HTTP endpoint для login/OTP.
- `app/engine.py`: общий предпросмотр и подтверждённая очередь для трёх типов. Retry/reconciliation используют прежний механизм.
- `app/controller.py`: общий регулятор с дополнительным hold для нулевого поискового трафика.
- `app/main.py`: строго типизированные запросы, session/CSRF/Origin, API и проектные сводки.
- `app/static/app.js`: единое модальное окно; canonical выбранный список — textarea, а checkbox отражает его. Поздний ответ запроса игнорируется по версии запроса/объекту мастера. Переключение типа инвалидирует ответы. Все внешние строки экранируются.

## API сервиса

Endpoints требуют существующей административной сессии. POST дополнительно требует точного Origin и `X-CSRF-Token`.

### `GET /api/discovery/status`

Возвращает `telegram_configured` (настройки и файл, не проверка активной авторизации), `tgmaps_mode="csv"`, число research-записей и TTL кэша. Без токенов и session-данных.

### `POST /api/discovery`

```json
{"kind":"bots","query":"Example_bot","mode":"similar","refresh":false}
```

`kind`: `bots|channels|search`; `mode`: `similar|search|manual|research`.

- `similar`: до пяти исходных usernames, один вызов рекомендаций для каждого.
- `search`: поиск части имени через Telegram; минимум три символа.
- `manual`: список целей для просмотра с собственными метриками и research.
- `research`: просмотр импортированных целей; query может быть пустым.
- Для `kind=search` выполняется локальный подбор фраз из запроса, истории, CSV и простых гипотез.

Ответ: `items`, `warnings`, `updated`, `telegram_total`, `history_note`. Элемент содержит `key`, `kind`, `username`, `title`, необязательные `audience`, `audience_metric`, `telegram_id`, `audience_updated`, `sources`, `history`, `research`, `research_count`, `availability="unchecked"`. Метрики аудитории не генерируются.

Telegram: `contacts.SearchRequest` с флагами bots/broadcasts; для рекомендаций — `bots.GetBotRecommendationsRequest`/`channels.GetChannelRecommendationsRequest`. Полученные сущности фильтруются по bot/broadcast и наличию username. Одна сессия, одна блокировка запросов, ленивое соединение, без автоматического входа/сообщений. В кэше сохраняются только используемые публичные поля, не полный MTProto User с потенциальными контактными данными.

### `POST /api/research/columns`

`{"csv":"..."}` → `columns`, `rows`, `sample` (до двух строк). Файл в браузере читается как UTF-8 с проверкой ошибок декодирования. Сервер принимает текст JSON, не произвольные пути к файлам.

### `POST /api/research/import`

```json
{
  "kind":"bots",
  "relation":"destination",
  "source":"TGMaps CSV",
  "csv":"target,text\nexample_bot,Example offer",
  "columns":{"target":"target","creative_text":"text"}
}
```

`relation`: `destination|placement|keyword`; keyword разрешён только для search. Обязательное сопоставление target; поля title, creative_text, destination_url, observed_at, detected_in необязательны. SHA256 нормализованной записи без времени импорта даёт идемпотентный ID. Проверка всех строк предшествует одной SQL-транзакции. CSV не исполняется, ссылки не загружаются. Значения ограничены по размеру. Импорт не создаёт рекламные задания.

### `POST /api/batches/preview`

```json
{
  "name":"VPN — каналы",
  "project":"Papin VPN",
  "kind":"channels",
  "targets":"durov\ntelegram",
  "template_id":"template-id",
  "budget":2,
  "cpm":5,
  "tracking":"keep",
  "policy":null
}
```

Для старых клиентов `kind` по умолчанию bots, прежнее поле `bots` принимается, если targets пуст и kind=bots. Смешивать оба поля нельзя. Существующие подписанные предпросмотры ботов и очереди продолжают работать.

`getTargetBot({bot_id:"@username"})` и `getTargetChannel({channel_id:"@username"})` проверяют площадки. Поиск проверяется локально и помечается `validation=local`. Рекламный API не имеет подтверждённого preflight-метода для поисковых фраз в этой реализации.

Неретраебельная ошибка отдельной площадки попадает в `rejected`. Транзитная ошибка прерывает весь preview. После разрешения цели объединяются по ID, рассчитывается бюджет оставшихся целей, проверяются лимиты и текущий баланс. Полный список разрешённых целей и шаблон включаются в HMAC-подписанный токен на 15 минут. Отдельный неподписанный список целей в create не принимается.

### `POST /api/batches`

`{"token":"signed-preview"}` → ID существующей/новой пачки. Все batch_items создаются одной транзакцией. Изменение типа, целей, шаблона или бюджета требует нового preview.

| kind | placement | target | text |
|---|---|---|---|
| bots | bot_banner | type=bots, bot_ids=[id] | текст шаблона |
| channels | channel_post | type=channels, channel_ids=[id] | текст шаблона |
| search | search_result | type=search, search_queries=[фраза] | пустая строка |

`username` в legacy batch_items теперь хранит значение цели: username или целую фразу. Поле не переименовано, чтобы сохранить очередь. Заголовок начинается с batch ID и ID задания до обрезки UTF-8 до 128 байт, сохраняя уникальность для сверки после неопределённой доставки; start-метка использует ASCII SHA256 цели и не содержит невалидных символов поисковой фразы. Search запрещает unique tracking ещё до создания token.

`GET /api/batches` дополнен kind/project и projects-сводкой. Показатели проектов берутся только по связанным ad_id, без двойного счёта внутри группы. Общий CTR/CPC — отношение сумм. Старые пачки относятся к bots / «Без проекта». Никакого перераспределения бюджетов между форматами нет.

## Данные и миграция

SQLite schema расширена аддитивно:

- `discovery_cache(key PRIMARY KEY, body, updated)`;
- `research(id PRIMARY KEY, kind, target_key, body, updated)`;
- индекс research(kind,target_key).

Batch kind/project находятся в существующем JSON spec. Placements шаблона находятся в JSON body, по умолчанию доступны три формата; содержимое и ссылка проверяются в preview. Отсутствие placements в старом шаблоне трактуется как три формата. Изменение шаблона не меняет существующие объявления/подписанные preview.

Применение схемы: `CREATE TABLE/INDEX IF NOT EXISTS` при запуске. Старые строки не удаляются и не переписываются. Перед обновлением создайте SQLite backup штатным API. Ранний откат к версии, поддерживающей только ботов, небезопасен при оставшихся заданиях channels/search: сначала отмените/завершите новые очереди и выключите их стратегии либо восстановите согласованную резервную копию.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
node --check app/static/app.js
git diff --check
```

`tests/test_app.py`: исходные auth/CSRF/финансовые и retry-тесты. `tests/test_discovery.py`: три payload, совместимость шаблонов, start/query/invite/post, дедупликация alias, частичные отказы и транзитные ошибки, локальная валидация фраз, кэш/refresh/stale, отсутствие аудитории, CTR/CPC истории, CSV mapping/отношения/повторы/атомарность/HTTPS, неавторизованный доступ, гипотезы без частотности, работа без Telegram, поисковая стратегия с нулём показов.

Браузерная проверка проводится на отдельном локальном приложении с поддельными Telegram/Ads API. Создание тестовой рекламы/смена ставок в рабочем кабинете запрещены. После deploy допустимы health, загрузка интерфейса, аутентифицированные чтения и рекомендация публичной площадки после авторизации аккаунта оператором.

## Дальнейшее подключение API TGMaps

Текущий контракт research сохраняет тип цели, отношение, источник и даты. Будущий адаптер API должен преобразовывать подтверждённые поля в этот же контракт и использовать те же правила дедупликации. До получения документации/доступа URL, методы, форматы и показатели API TGMaps не предполагаются. Парсинг личного кабинета с пользовательскими cookies и обход ограничений не реализованы.
