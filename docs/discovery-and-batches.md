# Подбор целей и массовый запуск

Реализованы три режима: боты (`bots`), каналы (`channels`), поиск (`search`). Один элемент пачки создаёт одно объявление с одной целью. Настройки не изменяют ранее созданную рекламу. Запросы рекомендаций, импорт CSV и предпросмотр не создают объявления и не выделяют средства.

## Работа пользователя

1. Сохраните шаблон: название, текст, Telegram-ссылка, частота и допустимые типы размещения. Для ботов и каналов текст обязателен. Шаблон только для поиска может иметь пустой текст.
2. Нажмите «Создать пачку», выберите тип. Поле «Проект» объединяет пачки в локальном отчёте сервиса; это не объект кампании в Telegram Ads.
3. Заполните выбранные цели вручную либо воспользуйтесь подбором. Ботов/каналы можно разделять пробелами, запятыми, точками с запятой или переносами. Поисковые фразы разделяйте переносом или `;`: пробел внутри фразы сохраняется.
4. Введите исходный username и нажмите «Найти похожие». Несколько исходных площадок — через запятую, максимум пять. При настроенной сессии ввод части имени запускает поиск Telegram с задержкой 650 мс; для найденной строки есть кнопка «Похожие на этого». Подбор выполняется на один уровень, рекурсивного сканирования нет.
5. Отметьте цели. Выбор хранится в поле списка и сохраняется при фильтрации, сортировке и обновлении результатов. При смене режима списки целей каждого режима сохраняются до закрытия окна. Сортировка и фильтры не снимают скрытые галочки.
6. Выберите бюджет **на каждое объявление**, начальную CPM, способ ссылки и при необходимости параметры стратегии. Счётчик показывает произведение числа уникальных выбранных целей на бюджет. Действует серверный лимит размера и суммы пачки.
7. Нажмите «Проверить и продолжить». Перед подтверждением отображаются разрешённые цели, исключённые площадки с причиной, итоговый бюджет, ссылка, текст/особенность поиска и предупреждения о повторных размещениях.
8. Только кнопка «Создать N объявлений» добавляет задания в очередь. Повторная отправка того же подтверждения возвращает ту же пачку. Ход создания и ошибки видны в «Массовом запуске». Отмена очереди не удаляет созданную рекламу.

## Что означает список результатов

- **Боты:** `bot_active_users` из Telegram — активные пользователи за месяц (MAU).
- **Каналы:** `participants_count`, когда присутствует в ответе Telegram, — подписчики. Дополнительное сканирование сообщений и вычисление среднего охвата не выполняются.
- **Поиск:** частотность неизвестна. Сервис не подменяет её аудиторией площадок и не обращается к несуществующему планировщику ключей.
- Отсутствующее число отображается как «Нет данных», а не 0. Сумма аудиторий не считается уникальным охватом.
- Порядок источника сохраняется. Доступны сортировки аудитории в обе стороны, собственного CTR по убыванию и CPC по возрастанию; неизвестные значения идут в конец.
- Фильтры: текст в названии/username; минимальная/максимальная аудитория; без собственных размещений; без активных объявлений; только со сведениями CSV; включать результаты без аудитории.
- **Ваша история** строится из объявлений рекламного кабинета: IDs, активные объявления, показы, клики, расход, CTR и CPC за всё время. Если объявление имеет несколько целей, его метрики относятся ко всему объявлению; это отмечено в строке. Их нельзя интерпретировать как измерение каждой цели. Групповые CTR/CPC вычисляются из суммы кликов/показов/расхода, а не средним арифметическим процентов.
- Каждая строка отмечает источник, время получения аудитории и доступные исследовательские записи. Сходство в процентах не выдумывается.

В режиме поиска введённые фразы дополняются совпадениями из собственной истории и CSV, а также простыми вариантами с суффиксами «бот» и «telegram», если они укладываются в предел длины. Эти варианты обозначены как **гипотезы**. Это не семантическая модель и не прогноз спроса. Оператор выбирает, какие варианты тестировать.

## Формат поиска

На одну фразу создаётся отдельный `search_result` с `target.type=search`, `search_queries=[фраза]` и пустым `text`. Это соответствует структуре существующих поисковых объявлений подключённого кабинета. Отображение объявления управляется Telegram.

Ссылка — `https://t.me/username`: без параметров (`start` включительно), fragment, invite и ссылки на пост. Режим уникальной start-метки для поиска недоступен. Текст шаблона не отправляется; предпросмотр явно сообщает об этом.

Фраза нормализуется: удаляются окружающие пробелы, повторные пробелы объединяются. Локальный предел — 32 символа; пустые фразы недопустимы. Фразы нечувствительно к регистру объединяются. Сервис не пытается обходить ограничения длины добавлением невидимых символов. Разрешённость фразы, минимальную CPM и доступность формата окончательно проверяет Telegram Ads при создании и модерации. Предпросмотр поиска имеет отметку `validation=local`: это не подтверждение платформы. Для ботов/каналов используются реальные методы проверки целей.

## TGMaps / исследовательский CSV

Автоматического API TGMaps в версии нет: подходящая документация и доступ не предоставлены. Поддерживается реальный импорт UTF-8 CSV с явным сопоставлением колонок. Если конкретная выгрузка TGMaps не содержит username бота или поисковых фраз, такие сведения получить из неё нельзя. Данные каналов нельзя импортировать как данные ботов.

Откройте «Импорт исследования из TGMaps / CSV»:

1. Выберите файл до 120 КБ, максимум 500 строк. Поддерживаются UTF-8 BOM, разделители `,`, `;` и tab, кавычки и переносы в кавычках. При иной кодировке сохраните файл в UTF-8.
2. Укажите смысл данных: **реклама ведёт в площадку**, **реклама замечена внутри площадки**, либо **поисковые фразы** (для search).
3. Обязательно сопоставьте колонку с username/фразой. Необязательные колонки: название, текст креатива, ссылка назначения, дата обнаружения, где обнаружено. Автоматически предложенные соответствия нужно проверить.
4. Импортируйте. Повторы тех же записей не добавляются. Общий предел хранения — 10 000 записей. Все строки проверяются до записи: некорректная строка отменяет весь импорт.
5. Нажмите «Показать импортированные цели» или выполните рекомендации: записи автоматически присоединятся к совпавшим целям того же типа.

Дата из CSV хранится как текст источника, без приписывания неизвестной временной зоны. Дата импорта хранится отдельно. Ссылки допускаются только HTTPS; сервер не посещает их. Изображения не загружаются. Текст выводится с HTML-экранированием. Числа аудитории из неизвестной колонки CSV не объявляются MAU: аудитория в таблице поступает из Telegram.

**Отсутствие записи означает «Нет данных», а не отсутствие рекламы.** Наличие креативов не доказывает эффективность, расход, CTR, CPC конкурента или доступность размещения. Эти показатели не выдумываются.

Пример формата: [research-example.csv](research-example.csv). Произвольная выгрузка поддерживается через сопоставление колонок, обязательного формата заголовков нет.

## Telegram: подключение оператором

Нужен отдельный пользовательский аккаунт. Telegram API ID/hash — параметры приложения; их недостаточно без авторизованной пользовательской сессии. Рекомендации нельзя получать обычным Bot API-токеном.

1. Войдите новым аккаунтом на <https://my.telegram.org>, откройте **API development tools**, создайте приложение. Сохраните `api_id`/`api_hash` в приватной `.env`:

```dotenv
TELEGRAM_API_ID=123456
TELEGRAM_API_HASH=replace_with_your_app_hash
TELEGRAM_SESSION_PATH=/data/telegram
DISCOVERY_CACHE_SECONDS=21600
```

2. После установки новой версии выполните на сервере из `/opt/papin-ads`:

```sh
docker compose stop app
docker compose run --rm app python -m app.telegram_login
docker compose up -d app
```

В интерактивном терминале введите номер, код из Telegram и при необходимости пароль 2FA. Ввод скрыт. Код/пароль не передаются через HTTP сервиса и не хранятся в Git. Сначала остановите приложение, чтобы два клиента не открывали одну сессию одновременно.

Для разработки на Mac, после установки зависимостей и заполнения локальной `.env`:

```sh
TELEGRAM_SESSION_PATH=./data/telegram DATA_DIR=./data .venv/bin/python -m app.telegram_login
```

Для запуска локального приложения задайте тот же `TELEGRAM_SESSION_PATH`.

3. Статус в мастере показывает наличие настроек и файла. Фактическая авторизация проверяется при запросе. Проверьте один подбор; реклама от этого не создаётся.

Сессия `telegram.session` — полноценная авторизация аккаунта. Используйте отдельный аккаунт без личной переписки. Храните файл в приватном data volume; CLI создаёт его с правами 600. `*.session` и временные session-файлы исключены из Git. Из интерфейса нельзя скачивать сессию, менять API ID/hash или выполнять вход. Для отзыва доступа завершите сессию в Telegram → Настройки → Устройства и удалите её файл при остановленном приложении. Сервис вызывает только поиск, разрешение username и рекомендации, не отправляет сообщения, не вступает в каналы и не запускает ботов.

Premium у подключённого аккаунта может расширять выдачу рекомендаций. Число результатов определяется Telegram. При наличии `count` больше возвращённого списка интерфейс сообщает о сокращённой выдаче.

## Кэш и ошибки

Ключ кэша: тип цели + режим + исходный запрос. Время жизни по умолчанию шесть часов. «Обновить» запрашивает свежие данные. При ошибке показывается сохранённая выдача с предупреждением и её временем, если она есть. Авторизация Telegram и запросы выполняются лениво: отсутствие Telegram не мешает кабинету и ручным пачкам.

Запросы Telegram сериализованы; включены короткие сетевые тайм-ауты и ограничение ожидания. `FloodWait` сохраняет время запрета повторов, приложение не спит на весь этот период. Ручные списки, CSV и история остаются доступны. При нуле рекомендаций интерфейс показывает пустую выдачу. Ошибка Telegram отображается отдельным текстом.

## Бюджет, стратегия и отчёты

Бюджет пачки — число разрешённых уникальных целей × бюджет объявления. Usernames нормализуются, а alias одного Telegram ID объединяются при рекламной проверке. Недоступные цели исключаются только с явным отображением в предпросмотре. Сетевая ошибка проверки прерывает предпросмотр вместо объявления площадки недоступной.

Проверяются свободный TON-баланс и лимиты сервиса. Между предпросмотром и исполнением баланс и правила платформы могут измениться; ошибка создания отображается у конкретного задания. Сервис не выполняет автоматическое пополнение бюджета.

Стратегия назначается каждому созданному объявлению отдельно. Для поиска при нуле показов за зрелое окно CPM автоматически не повышается: недостаточно данных о спросе, требуется проверка фразы/ставки оператором. При наличии показов действует обычная коррекция темпа и границы CPM. Для старых стратегий ботов и каналов алгоритм сохранён. Достижение цели не гарантируется доступным спросом.

В «Массовом запуске» есть сводка проекта по форматам и общий итог: число созданных объявлений, показы, клики, расходы, CTR/CPC. Она включает только связанные с пачками объявления, присутствующие в кабинете; импортированные старые объявления без связи с пачкой в эту сводку не входят. Метрики за всё время, не за период пачки. Неизвестные значения не заменяются нулём.
